# AI-метеоагент

Домашнее задание Light к занятию №9 Университета искусственного интеллекта. Агент отвечает на вопросы о текущей погоде и прогнозе на русском языке. В панели справа видны шаги, аргументы и результаты инструментов.

## Архитектура

```text
Чат → POST /api/chat → OpenAI API с Tool Calling
                ↕
   MCP-клиент → weather.chukai.io/mcp → Open-Meteo
                ↓
   События NDJSON, аргументы, результаты, ответ
```

Next.js работает в Node.js runtime. При каждом запросе официальный MCP TypeScript SDK подключается к [удалённому серверу](https://weather.chukai.io/mcp) через Streamable HTTP. Сервер возвращает каталог через `tools/list`. Модели передаются обнаруженные имена, первые абзацы описаний и схемы трёх инструментов.

| Инструмент | Назначение |
|---|---|
| `geocode_location` | Поиск города и его координат |
| `get_weather_forecast` | Текущая погода или прогноз по координатам |
| `interpret_weather_code` | Расшифровка кода погодных условий |

Модель выбирает функции через Tool Calling в OpenAI Chat Completions. Сервер отправляет запросы напрямую в `api.openai.com`. Для прогноза backend подставляет м/с и один день, если модель опустила эти параметры. В текущих данных WMO-код подписывается по [таблице Open-Meteo](https://open-meteo.com/en/docs#wmo-weather-interpretation-codes-ww). Backend последовательно выполняет до восьми вызовов `tools/call` и передаёт их результаты модели. Все запросы о погоде идут через MCP. Диагностика `/api/status` проверяет подключение и каталог инструментов.

Чат хранится в браузере. При каждом запросе сервер получает последние шесть завершённых обменов и новый вопрос. Фраза «А в Казани?» после вопроса про Екатеринбург сохраняет тему разговора и запускает новую цепочку вызовов. Кнопка «Новый диалог» очищает текущую историю и отменяет незавершённый запрос.

## Локальный запуск

Нужен Node.js 22 или новее.

```sh
npm ci
npm run dev -- --hostname 127.0.0.1 --port 3109
```

Откройте [локальное приложение](http://127.0.0.1:3109). После настройки отдельного ключа OpenAI в защищённом диалоге Codex он хранится в игнорируемом `.env.local`. Формат конфигурации приведён в `.env.example`.

| Переменная | Назначение |
|---|---|
| `OPENAI_API_KEY` | Серверный ключ проекта OpenAI |
| `OPENAI_MODEL` | Модель OpenAI с поддержкой Tool Calling в Chat Completions при `reasoning_effort=none`. По умолчанию `gpt-6-luna` |
| `MCP_SERVER_URL` | Адрес удалённого MCP. По умолчанию `https://weather.chukai.io/mcp` |

## Лимиты и расходы

На один вопрос разрешено до восьми вызовов инструментов и девяти обращений к модели. Сервер передаёт до шести предыдущих обменов, ограничивает каждый запрос к OpenAI 64 000 байтами и каждое завершение 512 токенами. Таймауты составляют 18 секунд на обращение к OpenAI и 52 секунды на весь запрос. В чате доступен один ручной повтор неудачного запроса. Автоматические повторы отключены.

Для `gpt-6-luna` 10 000 входных и 1 000 выходных токенов суммарно обойдутся примерно в $0,0015 по стандартному тарифу без кеширования. Оценка иллюстративная. Для учебного проекта можно настроить бюджет, уведомление и опцию **Enforce a hard limit** в разделе **Limits**. Лимит срабатывает с задержкой учёта расходов.

- [Тариф и возможности GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)
- [Настройки расходов проекта OpenAI](https://help.openai.com/en/articles/9186755-managing-projects-in-the-api-platform)

## Проверка

```sh
npm run typecheck
npm run build
npm run mcp:probe
```

В одном диалоге задайте «Какая сейчас погода в Екатеринбурге?» и «А в Казани?». В панели MCP выберите каждый вопрос и раскройте `get_weather_forecast`. В аргументах должны быть разные координаты. В ответе MCP видны текущие показатели, а рядом с записью виден статус.

Для контролируемой проверки ошибки остановите обычный экземпляр и запустите приложение со значением `MCP_SERVER_URL=http://127.0.0.1:3198/mcp`, где порт закрыт. Чат покажет ошибку подключения, запись в трассировке и кнопку «Повторить».

## Подготовка к публикации на Vercel

Версию с OpenAI API можно публиковать после одобрения локальной проверки. Для проекта Next.js на Vercel понадобится серверный секрет `OPENAI_API_KEY` в окружении **Production**. При необходимости задайте `OPENAI_MODEL` и `MCP_SERVER_URL`. После согласованного деплоя нужно открыть production-адрес и повторить сценарии с обоими городами и обработкой ошибки.

PDF-отчёт со скриншотами опубликованной версии готовится после этих проверок.
